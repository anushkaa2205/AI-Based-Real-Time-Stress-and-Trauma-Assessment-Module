# Privacy and Safety Rules Review
## AI-Based Real-Time Stress and Trauma Assessment Module (SIH26093)

Task 9.6 (AC-ETH-01, AC-PRI-01). Each rule in `CLAUDE.md` ("Rules that must never be broken") with the evidence that it holds. Reviewed 15 November 2026 against the code at that date. Evidence is a test (it fails if the rule breaks), a structural guarantee in the code, or a manual check (stated as such).

| # | Rule | Holds? | Evidence |
|---|---|---|---|
| 1 | **Victims never see scores.** Only `showEmergencyPanel` reaches them. | ✓ | Victim responses use strict Zod schemas (`MessageResponse`, `TurnResponse`, `AudioResponse` are `z.strictObject`) with no score fields, so extra fields fail. Tests assert the exact keys of victim responses and that no `svi`/`band`/indicator name appears (`voice.spec.ts`, `languages.spec.ts`, `victim.spec.ts`). Victim real-time channel `private-victim-{id}` carries only `emergency.show` (`lib/realtime/channels.ts`); `staffCanSubscribe` refuses victim channels. |
| 2 | **The AI never talks to the victim.** Prompts are scripted, pre-translated keys. | ✓ | All victim text comes from `messages/*.json` via `t()` / `next-intl`; operator suggested questions are the same keys (`core/conversation/suggest.ts`). The analysis service is only called for analysis (`/v1/analyze/*`, `/v1/summarize`). `npm run i18n:check` passes for all five languages. |
| 3 | **The AI finds indicators; rules compute the score.** | ✓ | SVI, bands, overrides and recommendations come only from `core/scoring` and `core/recommendations` (pure, 94% test coverage). The AI response schema has no score or band field (`analysis-client/schema.ts`). Voice: features → capped signals in `core/scoring/voice.ts`; the emotion model never sets a band. |
| 4 | **Two independent safety paths.** Lexicon on every message, before and regardless of the AI; victim endpoints never fail because of the AI. | ✓ | `run.ts` runs `lexiconSignals` before the AI call, in every consent mode; an AI failure marks `limitedConfidence` and queues a re-score (`AC-REL-01` tests). Rules-only evaluation flags 100% of suicide and danger scenarios (AC-NLP-06). Voice windows score from the lexicon on the transcript at once (AI deferred). Lexicon in six rule sets (en, hi, hinglish, mr, ta, bn). |
| 5 | **Safety overrides only raise the band; only a human, with a written reason, lowers a locked band.** | ✓ | `applyOverrides` takes the max of computed and override bands (unit tests); band override endpoint needs ≥ 5-character reason (`staff.spec.ts` AC-CASE-02); after a human override, only newer evidence can raise it again (FR-RISK-03 test). | 6 | **Consent before analysis**; the safety check runs in every mode. | ✓ | `runPipeline` refuses before consent (AC-CON-01); text AI only when `allowsTextAnalysis(mode)`; voice only when `allowsVoiceAnalysis(mode)` (`409 CONSENT_REQUIRED`, `voice.spec.ts`); the safety check and lexicon run in `SAFETY_ONLY` too. The service worker never caches pages or API responses (`pwa.spec.ts`). |

## AC-ETH-01: no diagnostic label on victim screens

Reviewed every victim screen and message file (manual check plus the response-shape tests above): start, consent, chat (all question types and the context form), voice recorder, emergency panel, closing screen, IVRS, offline page — in all five languages. Screener items are worded as questions about feelings ("Feeling down or hopeless"), never as results; no screen shows a band, score, "depression", "PTSD" or any condition name. The emergency panel says help is available, not why. ✓

## AC-PRI-01: identifiers separate from assessment data

Names, phones and addresses live only in `subject_identities` in the separate `nhaa_pii` database, linked by the pseudonymous `subjectId`; assessment collections hold no identifier. Identity reads need `identity.read` and are audited (`identity.view`). ✓
